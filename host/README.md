# Программа на ноутбуке

Пакет `balancing_host` реализует приём BLC1, CRC, CONFIG/UUID/epoch, ограниченный decoder, неизменяемый raw-архив, replay, 1×/FFT/синхронное усреднение и математическую двухплоскостную коррекцию. Подготовка G02/G07 проверена на синтетике; устройство и точность стенда ещё не приняты.

Установка из корня с uv:

```powershell
uv sync --frozen
uv run balancing --help
uv run python -m unittest discover -s tests -v
```

Проверено с Python 3.12.6 и uv 0.12.13. Runtime lock: NumPy 2.5.4, SciPy 1.18.1, PySerial 3.5 на этой версии Python. Остальные варианты из uv.lock не проходили отдельную приёмку.

Для non-editable проверки в pyproject.toml включены cache-keys исходников host: после изменения .py uv должен обновлять wheel. Поведение по умолчанию и настройка описаны в [официальной документации uv](https://docs.astral.sh/uv/concepts/cache/). Инструмент tools/check_installed_sources.py побайтно сравнивает установленный wheel с проектом; его запускают Python из отдельной non-editable среды.

## Работа без приборов

Запустить экран дисбаланса с 3D-люлькой, двумя плоскостями и сравнением «до / после»: `uv run balancing demo --open`. Это отдельный synthetic UI без USB/BLC1; методика и ограничения: [DEMO](../docs/DEMO.md).

```powershell
uv run balancing simulate --output data/runs/demo --seconds 3 --rpm 600
uv run balancing inspect data/runs/demo
uv run balancing replay data/runs/demo --output data/runs/demo/replay.jsonl
uv run balancing analyze data/runs/demo --source 0 --output data/runs/demo/analysis.json
```

Каждый output создаётся впервые; существующие данные не перезаписываются. Повторный пример использует новое имя каталога/файла. simulate всегда ставит SIMULATED и `data_kind=synthetic`. Анализ поддерживает один выбранный источник с полной согласованной сессией/эпохой; другие источники выбираются `--source 1`, `2`, `3`. Он консервативно отказывает при ошибках/качестве, неизвестной задержке и нескольких эпохах. Автоматического выбора чистых сегментов пока нет.

`analyze` пишет пиковую амплитуду и фазу 1×, синхронное среднее и диагностический FFT-пик для стационарного окна. Угол — относительно принятой метки. Это движение площадки датчика; без коэффициентов влияния нельзя указать место снятия металла.

## Реальный USB после аппаратных проверок

```powershell
uv run balancing record --port COM_N --kind bench --seconds 20 --start --output data/runs/bench-new
```

`COM_N` — пример, заменить подтверждённым портом своей платы. Этот путь в текущем раунде не выполнялся. Импорт пакета не сканирует и не открывает COM. `--start` выполняет handshake/GET_CONFIG/START, а при возможности STOP и ограниченный drain; команды не управляют мотором. Без `--start` захват пассивный. Он может не иметь END, если устройство не завершило сеанс. Неопределённый исход команды или разрыв сохраняется как незавершённая запись.

CLI record возвращает ненулевой код при незавершённом/некорректном capture; сохранённые файлы остаются доступны. Управляющая логика проверена control-only эмулятором без отсчётов и реального порта; он не заменяет USB-приёмку устройства.

## Сохранность и replay

Архив: `raw.blc`, `events.jsonl`, `metadata.json`. Исходные байты записываются до разбора, включая мусор и плохой CRC. HOST_CHUNK в журнале сохраняет границы/время получения для воспроизведения CONFIG timeout; времена измерений остаются аппаратными. Standalone raw без companion journal не восстанавливает host arrival timing. При replay ошибки decoder можно получить callback; CLI пишет их как HOST_DIAGNOSTIC.

Размер входного chunk ≤64 КиБ, буфер поиска ≤16 КиБ, история диагностики ≤64 событий, одна собираемая CONFIG ≤8192 байт. Входные очереди не растут вместе с файлом. Сброс на диск — периодически (1 с) и при штатном закрытии. Реальная потеря питания/буферы накопителя не испытаны. `closed` означает закрытый архив, а не успешную балансировку; проверяется END/качество/хеш.

## Две плоскости и неопределённость

`analysis.influence_matrix` принимает baseline и две независимые пробы. `solve_correction` использует полную ковариацию Re/Im каналов, whitening и четыре вещественные неизвестные. Масса добавляется по выданному углу; удаление эквивалентно направлению +180°. Возвращаются ранг, условность, остаток, условная ковариация и её ограничения. Неизвестное синхронное воздействие привода автоматически не отделяется.

CLI `solve` читает JSON с `H_real`, `H_imag`, `V_real`, `V_imag`, `covariance_real`, `data_kind` и необязательными `limits` (reference_gmm, max_std_gmm, max_condition, min_residual_p). Это математическая операция с явно заданной калибровкой; её получение/физический holdout относятся к G10.

`uncertainty.bootstrap_runs` пересчитывает H и коррекцию по независимым повторным прогонам. Не передавать ему отдельные коррелированные отсчёты как «независимые прогоны». Систематическая ошибка грузов/геометрии/привода остаётся отдельным бюджетом G12.

Для α предусмотрена оконная локальная модель `Phase.kinematics(window_s=...)`; двойное дифференцирование квантованных tooth timestamps не применяется. У окна есть ограничение по краям и частотная характеристика. Одна метка за оборот не устанавливает внутриоборотное ускорение.
