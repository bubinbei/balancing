# Демо экрана дисбаланса

Это запускаемый локальный экран, уровень **synthetic**. Оборудование не требуется; программа не открывает COM и не управляет приводом. Реальная точность стенда не подтверждена.

## Запуск

Из корня репозитория:

```powershell
uv sync --frozen
uv run balancing demo --open
```

В терминале появится `SYNTHETIC DEMO: http://127.0.0.1:PORT/`; браузер откроется по этому адресу. PORT автоматически выбирается из свободных. Сервер доступен только на этом компьютере. Чтобы остановить его, нажать Ctrl+C в терминале. Для фиксированного порта: `uv run balancing demo --port 8765 --open`; занятый порт даёт ошибку, чужой процесс не завершается.

## Что показано

- Увеличенная 3D-люлька с коленвалом; перетаскивание меняет ракурс, кнопка переключает вид с торца. Люлька полупрозрачная, металлические детали перекрывают друг друга по глубине. Верх длинных подвесов может выходить за границу крупного вида.
- Плоскости A/B: оценка дисбаланса в г·мм, эквивалентная масса при радиусе 100 мм и угол добавления массы.
- Полярные стрелки обозначают направление, их длина условна. Сплошная — оценка тяжёлой стороны; пунктир — добавление массы. Для удаления направление противоположно добавлению, но обработка реальных деталей этим демо не разрешается.
- Углы в обеих плоскостях: 0° сверху, по часовой стрелке при взгляде A→B и положении индексной метки 0°. Это единая условная система демо, не измеренная ориентация реального датчика фазы.
- Цвет люльки — модельное ускорение RMS, не карта массы. Увеличение движения ×6000 и цветовая шкала сохраняются между «до» и «после» одного случая.
- Три случая: разный дисбаланс концов, силовой, моментный. В моментном случае поступательное движение может отсутствовать, хотя дисбаланс в обеих плоскостях есть.

Анимация показывает один замедленный цикл за 8 секунд и останавливается; при системной настройке уменьшения движения кнопка переключает отдельные фазы.

3D использует встроенный WebGL без внешних runtime-библиотек. Если WebGL недоступен, внутри модели появляется сообщение; таблицы расчёта остаются доступны. Alpha поверхности люльки 0,18: наложение нескольких граней делает её визуально темнее. Цвет сохраняет смысл ускорения, прозрачность не означает иной материал или жёсткость. [Проверка расчётов и исправление перекрытия деталей](../evidence/reports/G07/analysis-review.md).

## Полоска, восемь противовесов и снятие массы

Со слов владельца у коленвала восемь противовесов: четыре центральных направлены в одну сторону, по два крайних — в противоположную. В интерфейсе CW1–CW8 идут от приводного шкива A к маховику B; центральные CW3–CW6 в нулевом положении вверх («север»), остальные вниз («юг»). 3D-модель показывает секторные противовесы, а карта — расположение в нулевом положении. Выбор CW останавливает изображение в нуле и подсвечивает его.

Фазовая полоска в демо расположена на приводном шкиве. При индексе 0° она сверху и совпадает по направлению с центром центральных противовесов. Кнопка «Полоска 0°» возвращает это положение; отсчёт в обеих плоскостях по часовой стрелке при взгляде A→B. Реальный монтаж/порог оптического датчика и фазовая калибровка не подтверждены. Положение полоски в демо — выбранная система отсчёта, не наблюдение реальной детали.

Угол добавления массы и угол снятия отличаются на 180°. A/B — расчётные плоскости, не номера CW. Разрешённая для снятия зона, осевая координата и радиус реального противовеса нужны отдельно. Принцип коррекции двумя плоскостями и добавлением/удалением массы: [Brüel & Kjær](https://www.bksv.com/doc/bo0276.pdf).

`counterweights.plan_two_point_removal` перебирает пары CW, переводя две комплексные добавляемые коррекции C_A/C_B в положительные массы удаления с сохранением суммарного дисбаланса и осевого момента:

```text
R_i + R_j = -(C_A + C_B)
x_i R_i + x_j R_j = -(x_A C_A + x_B C_B)
m_i = abs(R_i) / r_i
```

R — вектор снятия, г·мм; x и r — мм. Требуемый угол каждого R должен попадать в заданный сектор своего CW. Из подходящих пар выбирается наименьшая суммарная снимаемая масса; это не поиск оптимума по всем возможным много-точечным коррекциям и не локализация исходного дефекта. Если подходящей пары нет, интерфейс явно сообщает это. Вариант без пары не доказывает невозможность коррекции большим числом точек.

Демо-геометрия **не измерена**: A/B x=±340 мм, CW x=[-260,-190,-110,-40,40,110,190,260] мм, радиус коррекции 65 мм, сектор каждого CW ±55° вокруг севера/юга. Сектор соответствует нарисованной форме, но не является утверждённой зоной обработки. Таблица и крестики показывают только учебный вариант: числа нельзя переносить на реальную деталь. Не заданы толщина, прочность, масляные каналы, допустимая глубина/диаметр отверстий и предел удаления металла.

«После коррекции» по-прежнему моделирует исходную коррекцию в A/B, а не реальное сверление CW. Эквивалентность переноса на CW проверена отдельными численными тестами сохранения силы/момента; аппаратной проверки нет.

## Откуда берутся числа

`balancing_host.demo.build_demo` создаёт сигналы четырёх каналов: поперечные ускорения концов A/B, угловые скорости крена/yaw. Частота 800 Гц, 4 с, 900 об/мин, seed 52840. Данные не проходят BLC1/raw/USB: этот экран проверяет другой, явно ограниченный путь.

Для каждого случая создаются исходный прогон и две пробы по 100 г·мм. Существующий `harmonic_fit` оценивает комплексные 1×-отклики; `influence_matrix` строит матрицу по пробам, `solve_correction` вычисляет коррекцию. Затем генератор применяет коррекцию к исходному дисбалансу и создаёт отдельный контрольный прогон с новыми шумовыми отсчётами. После расчётной коррекции остаток не подменяется нулём.

3D-движение строится по известному входу генератора; оценка дисбаланса — по сигналам с шумом. Модель условная: подвижная масса 15 кг, заданные инерции и жёсткая люлька, без реальной передаточной функции. 13,05 кг — сообщённая масса только коленвала; масса маховика/шкива и полная масса пока неизвестны. Графическое увеличение включает коррекцию геометрии, сохраняющую длину обеих нарисованных струн.

Не проверены: подключение NiceNano, реальные шум/фаза MEMS, монтаж, смазка, механика, получение калибровки на станке и предел обнаружения. Ковариация solver условна при известной H; неопределённость пробных грузов и ошибки модели в демо не оценены. G00/G06 остаются blocked; демо не повышает статусы аппаратных этапов.

## Проверки

```powershell
uv run python -m unittest tests.analysis.test_demo -v
uv run --no-project --with playwright python tools/check_demo_ui.py http://127.0.0.1:PORT/
```

Вторая команда требует установленный Google Chrome; путь меняется аргументом `--chrome`. Playwright — только средство приёмки UI, не runtime-зависимость. Результаты и снимки по умолчанию локальны: `evidence/local/demo-ui/`. Проверяются значения против Python JSON, все три случая/два состояния, 320/360/1280 px, светлая/тёмная темы, длина струн и конечность анимации.

Навигация: [программа ноутбука](../host/README.md), [STATE](../STATE.md), [отчёт G07](../evidence/reports/G07.md).
