# Публикация

Владелец разрешил публичные репозитории GitHub и Gitea. Локальное имя проекта и репозитория — `balancing`. Ожидаемые имена remote: `github` для GitHub и `origin` для Gitea. Адреса берутся из локальной Git-конфигурации; токены в файлы проекта не записываются.

Первоначальная поставка 2026-10-29 содержала только план; следующим запросом владелец поручил начать его реализацию. Создание репозиториев и первоначальная публикация относятся к [P00](../tasks/P00-project-setup.md), итоговая публикация реализации — к [G14](../tasks/G14-release.md). Команды ниже являются инструкцией; фактические результаты записываются в [отчёт P00](../evidence/reports/P00.md) и будущий отчёт G14. `tools/check_project.py` реализован в P00.

Публичная видимость репозитория Gitea не означает доступность локального сервера из Интернета. Эти свойства проверяются и сообщаются отдельно.

## До коммита

```powershell
python tools/check_project.py
git status --short
git diff --check
git diff
git diff --cached --check
git diff --cached --stat
git diff --cached
```

Просмотреть новые файлы и историю, проверить происхождение, внутренние ссылки, статусы этапов и отсутствие секретов/реальных сырых данных. Не публиковать `.obsidian/workspace*.json`, содержимое `data/runs/` и `evidence/local/`. Общедоступные отчёты должны быть обезличены.

## Публикация одной и той же ревизии

```powershell
git push origin main
git push github main
git rev-parse HEAD
git ls-remote origin refs/heads/main
git ls-remote github refs/heads/main
```

Три SHA должны совпасть. Затем открыть страницы/API обоих репозиториев и проверить `private=false`, ветку и доступность README без аутентификации. Не заменять эту проверку сообщением успешного push.

Если одна площадка не приняла push, сохранить локальный коммит и явно сообщить частичную поставку. Не force-push, не менять историю и не удалять чужой существующий репозиторий.

## Что означает первая поставка

Первая публикация содержит план, контракты, шаблоны, схему и созданную в P00 проверку документации. Наличие репозитория не означает существование прошивки, программы захвата или принятого станка. Этапы G00–G14 остаются planned до фактического начала и приёмки.
