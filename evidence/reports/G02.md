# G02 — приём, запись и replay на синтетике

Создан Python-пакет [balancing_host](../../host/README.md) и [uv.lock](../../uv.lock). Реализованы все wire-типы BLC1, CRC, ограничения полей/JSON, одна CONFIG с SHA256/timeout, UUID/epoch, последовательности и качество. Decoder имеет входной буфер ≤16 КиБ и историю последних ≤64 ошибок. Он выдаёт кадры итератором, а не копит все кадры в памяти.

Recorder пишет исходные байты до разбора и отдельно журнал. HOST_CHUNK сохраняет приёмное время/границы для точного воспроизведения CONFIG timeout. Отсутствующий END не фабрикуется. После штатного закрытия проверяется SHA raw; исходные байты не переписываются. Реализован ограниченный CommandClient (одна команда, до трёх идентичных повторов) и явно вызываемый PySerial adapter.

## Проверки

- Независимые [golden-векторы](../../tests/fixtures/synthetic/protocol-vectors.json) получены to_bytes + побитовым CRC, без production encoder/struct/zlib. Генератор хранится рядом для проверки происхождения.
- Проверяются все позиции разрыва каждого golden-кадра, склейка, magic внутри payload, плохие CRC/длины/версии/reserved, отрицательные i16 и максимальный кадр 1052 байта.
- Проверяются JSON duplicate keys/NaN/глубина/длины, CONFIG SHA/повтор/конфликт/timeout, неизвестные источники, новый UUID и wrap sequence.
- Raw/replay совпадают на синтетическом архиве; повреждённые байты/хвост сохраняются; ошибки decoder повторно доступны при replay. Checked short write, injected disk full, несовпадение финального хеша и аварийный выход отдельного процесса.
- Python client проверяет UUID/request_id/opcode ACK, конечные повторы, неизменность повторяемых байтов и неопределённый исход timeout.
- Control-only emulator проверяет handshake/START/STOP и отказ START без доступа к Serial. Он не генерирует отсчёты датчиков. CLI record проверяет завершённость/качество архива; деградированный END, TIME_UNCERTAIN и pending GAP не дают чистый capture.

Первый smoke-тест выявил 34-символьный UUID генератора вместо 32: HELLO был правильно отвергнут. Исправлен генератор, добавлены независимые wire-проверки. Неудачный synthetic smoke остался локально; не выдан за успешный захват.

## Границы

Программные проверки проходят; **этап не passed**, потому что G00 не принят и MCU-контрагент отсутствует. Реальный USB/COM, драйверы датчиков и кэш повторных команд на устройстве не испытывались. Результат `closed` в metadata означает закрытие файлов, а не отсутствие ошибок/успех измерения.
