# Balancing

Самостоятельный проект экспериментального стенда для динамической проверки и балансировки коленвала с маховиком и шкивом. Измерения собирает **NiceNano / nRF52840**, обработку выполняет **ноутбук**. Первый транспорт — **USB**, Bluetooth отложен.

**Реализована программная подготовка:** host/CLI для BLC1, raw/replay, 1×/FFT/двухплоскостной расчёт, synthetic-тесты и переносимое C-ядро. Аппаратная интеграция клона NiceNano и станок ещё не приняты. Точность 1 г не подтверждена. Рабочая цель проверки — **100 г·мм**, например 1 г на радиусе 100 мм, с отдельной оценкой погрешности.

## Начать следующий раунд

1. Прочитать [правила](AGENTS.md) и [текущее состояние](STATE.md).
2. Следовать STATE и [ROADMAP](docs/ROADMAP.md). P00 завершён; G00/G01 ждут фактическую плату/загрузчик, независимая подготовка G02/G07 и следующих программных срезов сохранена с отчётами.
3. Затем перейти к [G00: паспорт оборудования](tasks/G00-board-passport.md). Если физической платы рядом нет, заполнить подтверждённую часть и оставить аппаратные поля неизвестными.
4. После каждого раунда записывать фактические проверки и обновлять состояние. Проверка документации уже доступна: `python tools/check_project.py`.

Программой уже можно пользоваться без приборов:

```powershell
uv sync --frozen
uv run balancing simulate --output data/runs/demo --seconds 3 --rpm 600
uv run balancing analyze data/runs/demo --source 0 --output data/runs/demo/analysis.json
```

Подробности и ограничения: [программа ноутбука](host/README.md), [native C](firmware/BUILD.md), [промежуточный пакет доказательств](evidence/reports/AUDIT_PACKAGE.md). Output должен быть новым: записи не перезаписываются.

Полный порядок P00 → G00–G14 и зависимости: [дорожная карта](docs/ROADMAP.md). Правила небольших заданий для модели: [руководство исполнителю](docs/IMPLEMENTATION_GUIDE.md). После выполнения этапов подготовить [пакет для итогового аудита](docs/AUDIT_HANDOFF.md).

## Что исследуем

Лёгкая жёсткая деревянная люлька без тяжёлого блока двигателя, два полноценных металлических узла опор, подвесы и датчики около обоих концов вала. Две струны — исследуемый вариант, четыре круглых подвеса — альтернативная конфигурация, если она даёт лучшую повторяемость. Качание и поворот люльки включаются в модель; само увеличение числа каналов не гарантирует точность.

Предварительный измерительный комплект: два BMI160 с акселерометрами и гироскопами, два LIS3DH для дополнительных ускорений, угловые метки и индекс оборота. Поддерживаются будущие прогоны разгона, выдержки и торможения. Режимы и реальные модули подтверждаются поэтапно.

## Граница этой поставки

Первоначальная поставка от 2026-10-29 содержала план; затем выполнен P00 и начата автоматическая подготовка следующих этапов. Два BMI160, два LIS3DH и KY-033 заказаны; схема/ревизия клона, реальные GPIO/Flash layout и ротор неизвестны. Все данные текущих проверок synthetic/model_example. Полная аппаратная приёмка и итоговый аудит ещё впереди; текущие границы сохранены в [STATE](STATE.md) и отчётах.

Репозитории: [GitHub](https://github.com/bubinbei/balancing), [Gitea](http://192.168.1.124:3000/bubinbei/balancing). Оба публичные; адрес Gitea находится в локальной сети.

Отдельная лицензия на использование и распространение пока не выбрана. Проверка ссылок и структуры плана не является испытанием электроники, механики или точности балансировки.

## Проверка документации

Требуется Python 3.10 или новее; сторонние библиотеки не нужны. Из корня:

```powershell
python tools/check_project.py
python -m unittest discover -s tests/documentation -v
```

Checker читает исходники, проверяет ссылки, JSON/XML, карточки и зависимости. Он не открывает COM, не меняет файлы и не подтверждает истинность аппаратных отчётов. Параметры: `--json` для машинного вывода; `--root PATH` для проверки отдельной копии. Локальные измерения и кеши исключены. Ошибки дают код возврата 1, успешная проверка — 0.

Host требует Python ≥3.11 и зависимости из uv.lock; проверен Python 3.12.6. Все программные тесты: `uv run python -m unittest discover -s tests -v`. На текущей Windows-машине полный набор вместе с native C: `powershell -File tools/run_checks.ps1 -Native` (требуется Visual Studio 2019 Build Tools).
