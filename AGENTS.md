# Balancing — правила работы

Это самостоятельный проект гаражного балансировочного стенда. Все пути и имена файлов — ASCII; документация — на русском. Корень репозитория является хранилищем Obsidian. Использовать обычные относительные Markdown-ссылки.

Перед задачей прочитать только README.md, STATE.md и одну текущую карточку из tasks/. Остальные документы — по ссылкам из карточки. Не загружать весь архив и не повторять историю.

Принятые решения владельца: NiceNano / nRF52840; вычисления на ноутбуке; USB первым, Bluetooth позднее; два измерительных конца, многоканальные ускорения и угловые скорости; разгон, выдержка и торможение; публикация на GitHub и Gitea в публичных репозиториях.

Один рабочий раунд — одна карточка или явно ограниченная часть карточки. Сначала назвать результат, ограничения, критерии приёмки и затрагиваемые файлы. Не менять договорённости молча. Не расширять аппаратную платформу.

План, симуляция, успешная сборка и реальное аппаратное испытание — разные уровни доказательств. Ни один физический этап не считается пройденным без записи условий и фактических результатов. Не выдумывать измерения, подключённые устройства, форму сигнала и точность в граммах.

До подтверждения ревизии платы и схемы модуля не фиксировать распиновку как проверенную. До отдельной задачи не прошивать платы, не открывать COM, не запускать привод и не менять загрузчик. Эта первоначальная поставка — документация и средства проверки документации, не прошивка и не готовый станок.

Сохранять сырые записи, временные отметки, пропуски и настройки. USB-пакет не задаёт время измерения. Частота SPI не задаёт частоту измерений. Разные датчики имеют разные часы и задержки. Ошибки и переполнения должны быть видимыми; очереди ограничены.

Механику, калибровку, коэффициенты влияния и настройки идентифицировать версиями. Не переносить калибровку между разными подвесками, креплениями, приводами и настройками датчиков без проверки.

Не импортировать код, журналы, бинарники, закрытые спецификации и реальные измерения других проектов. Использовать самостоятельные материалы и первичные публичные источники из docs/SOURCES.md. Не включать токены, локальные учётные данные и идентификаторы устройств в Git.

Первоначальная поставка 2026-10-29 содержала только план. Последующим запросом владелец поручил начать его реализацию по P00 и G00–G14. Выполнять одну текущую карточку за раунд, сохраняя её критерии и аппаратные ограничения. После выполнения этапов подготовить пакет docs/AUDIT_HANDOFF.md и передать владельцу для отдельного аудита. Не объявлять аудит выполненным самим исполнителем.

После раунда обновить STATE.md (до 2500 символов), добавить запись в RECENT.md, указать текущую карточку, проверки, границы подтверждённого и следующий конкретный шаг. После реализации P00 запускать python tools/check_project.py и git diff --check. До P00 проверять документы непосредственно; отсутствие будущего скрипта не выдавать за успешный запуск. Статусы всех ещё не реализованных этапов оставлять planned.

Публиковать только проверенный индекс. Не применять force-push и не переписывать историю. После push сверить HEAD с git ls-remote на каждой площадке и проверить фактическую видимость репозитория. Частичный результат сообщать явно.
