# G05 — четыре датчика и устойчивый поток USB

**Результат:** два BMI160 и два LIS3DH записываются одновременно с явными потерями, ограниченной памятью и проверяемым повтором. Уровень: `device`; ротор не вращается.

**Читать:** [README](../README.md), [STATE](../STATE.md), эту карточку, [HARDWARE](../docs/HARDWARE.md), [FIRMWARE](../docs/FIRMWARE.md), [DATA_PROTOCOL](../docs/DATA_PROTOCOL.md).

**Файлы:** `firmware/` scheduler/transport/drivers, `host/` USB recorder, `tests/integration/`, `evidence/reports/G05.md`. Pinmap сверять с G00, не разводить заново по памяти.

## Срезы

1. Добавлять по одному модулю: отдельные CS и DRDY, проверка ID/readback. Настройки: BMI160 accel+gyro Normal 800 Гц; LIS3DH HR 1344 Гц. У LIS3DH сохранять корректный формат значимых битов; возможность FIFO/HR должна быть подтверждена выбранным способом чтения.
2. На SPI 4 МГц проверить обслуживание новых данных без голодания одного сенсора. Одновременное чтение нескольких DRDY не делает датчики синхронными; timestamps остаются отдельными. 8 МГц разрешить только после сравнения стабильности. 10 МГц не выбирать как стандартную частоту nRF, 16 МГц превышает лимит датчиков.
3. Собрать пакеты по DATA_PROTOCOL, ограничить TX ring 64 КиБ и отдельно capture/control очереди. При переполнении применять согласованную политику drop-newest, счётчики и GAP; ошибки должны оставаться видимыми после освобождения очереди.
4. Проверить 10 минут реальных неподвижных данных и отдельный 10-минутный синтетический USB stress 250 кБ/с **закодированного** потока. Маркировать эти записи разными источниками; стресс не заменяет работу SPI.
5. Остановить чтение host на 2 секунды, затем возобновить. Убедиться, что сбор продолжался по ограниченной политике, пропуски объявлены, накопление памяти не росло бесконечно. Переподключение и длительность — G13.

## Приёмка

- `PASS`: четыре верных ID, readback и стабильных независимых sample_seq; частоты соответствуют допускам датчиков, нет молча повторённых отсчётов.
- `PASS`: в нормальных 10-минутных опытах ноль CRC ошибок и необъяснённых потерь; для стресс-потока достигнуты 250 кБ/с по измеренной длине сохранённого encoded потока.
- `PASS`: stall вызывает видимые GAP/counters, затем полезные данные восстанавливаются; RAM и все очереди не превышают записанные лимиты; ни ISR, ни acquisition не ждут USB без ограничения времени.
- `FAIL`: объявлено «без потерь» только по скорости COM, неподтверждённые потери заменены точным числом или сбор остановился вместе с host.

**Откат:** сохранить прошивку одного датчика, уменьшить набор активных модулей для локализации; не понижать ODR или выключать каналы скрытно.

**Доказательства:** G05: настройки и версии, три разных опыта, продолжительность/байты, counters, максимумы очередей, частоты каждого сенсора, GAP и raw hashes.

**Завершение:** STATE/RECENT, проверки проекта и diff. Приёмка USB не является приёмкой фазовых задержек MEMS.

Отдельно проверь реальные данные и синтетический USB stress; привод не включай. Зафиксируй пропускную способность, RAM и восстановление после stall.
